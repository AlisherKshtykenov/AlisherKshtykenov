# ROADMAP-PREPROCESSING
    

## 1. Missing: Detection (поиск пропусков)

| Method (метод) | Идея | Когда применять | Особенность |
|---|---|---|---|
| **Missing report (отчёт о пропусках)** | Сколько пропусков в каждом столбце, в процентах | Всегда, первым делом | Пропуск может быть замаскирован: 0, −999, «unknown» |
| **Missing pattern (структура пропусков)** | Случайны ли пропуски или связаны с другими признаками | Перед выбором способа заполнения | Если пропуск неслучаен, **сам факт пропуска несёт информацию** |

## 2. Missing: Imputation (заполнение пропусков)

| Method (метод) | Идея | Когда применять | Особенность |
|---|---|---|---|
| **Drop (удаление)** | Удалить строки или столбцы с пропусками | Пропусков мало, или столбец почти пустой | Теряешь данные. При неслучайных пропусках искажает выборку |
| **Mean / Median / Mode (среднее / медиана / мода)** | Заполнить средним, медианой или самым частым | Быстрый базовый вариант | Медиана устойчива к выбросам. Все методы уменьшают разброс |
| **Constant (константа)** | Заполнить −1 или «unknown» | Категории, деревья | Деревья легко отделяют такое значение |
| **Forward / Backward fill (заполнение соседним)** | Взять предыдущее или следующее значение | **Временные ряды** | Бессмысленно, если строки не упорядочены |
| **Interpolation (интерполяция)** | Провести линию между соседними значениями | Временные ряды, плавные сигналы | Не работает для категорий |
| **KNN Imputer (заполнение по соседям)** | Взять значение у похожих объектов | Признаки связаны между собой | Медленный на больших данных, нужен scaling |
| **Iterative Imputer, MICE (итеративное заполнение)** | Предсказать пропущенный признак моделью по остальным | Много пропусков, сильные связи | Самый точный и самый медленный |
| **Missing Indicator (индикатор пропуска)** | Добавить столбец «здесь был пропуск» | Вместе с любым заполнением | Сохраняет информацию о том, что значение отсутствовало |

## 3. Outliers: Detection (поиск выбросов)

| Method (метод) | Идея | Когда применять | Особенность |
|---|---|---|---|
| **IQR (межквартильный размах)** | Выброс, если дальше 1,5 × IQR от квартилей | Один признак, любое распределение | **Самый частый базовый метод**. Это и есть усы boxplot |
| **Z-score (стандартизованное отклонение)** | Выброс, если дальше 3 стандартных отклонений от среднего | Распределение близко к нормальному | Сами выбросы сдвигают среднее и разброс, и метод их недооценивает |
| **Modified Z-score (модифицированный Z)** | То же через медиану и MAD (медианное отклонение) | Есть сильные выбросы | Устойчив, потому что медиану выбросы не двигают |
| **Isolation Forest (изолирующий лес)** | Выброс легко отделить несколькими случайными разрезами | Много признаков сразу | Ловит выбросы, невидимые по одному признаку |
| **LOF (локальный фактор выброса)** | Выброс, если вокруг него плотность ниже, чем у соседей | Данные с кластерами разной плотности | Находит локальные выбросы |
| **DBSCAN (кластеризация по плотности)** | Точки, не попавшие ни в один кластер, это шум | Есть естественные группы | Чувствителен к параметрам eps и min_samples |

## 4. Outliers: Treatment (обработка выбросов)

| Method (метод) | Идея | Когда применять | Особенность |
|---|---|---|---|
| **Remove (удаление)** | Убрать строку | Выброс точно ошибка ввода | **Нельзя, если выброс и есть то, что ищешь** (мошенничество) |
| **Clip / Winsorizing (обрезка)** | Заменить крайние значения на границу, например, 1-й и 99-й процентиль | Выбросы настоящие, но мешают модели | Сохраняет строку, убирает влияние экстремума |
| **Log transform (логарифм)** | Сжать длинный хвост | Цены, доходы, количества | Только для положительных значений (или log1p для нуля) |
| **Impute (замена как пропуск)** | Сделать выброс пропуском и заполнить | Выброс явная ошибка, но строка нужна | Комбинируется с любым методом из раздела 5 |
| **Flag (пометка)** | Оставить и добавить признак «это выброс» | Выброс может быть полезным сигналом | Модель сама решит, важен ли он |

## 5. Encoding (кодирование категорий)

| Method (метод) | Идея | Когда применять | Особенность |
|---|---|---|---|
| **One-Hot (прямое кодирование)** | Каждая категория — отдельный столбец 0/1 | Мало категорий, линейные модели, нейросети | **Стандарт.** При тысяче категорий тысяча столбцов |
| **Label (меточное)** | Каждой категории номер: 0, 1, 2 | Целевая переменная, деревья | Линейная модель решит, что 2 «больше» 1, хотя это не так |
| **Ordinal (порядковое)** | Номера по смыслу: «низкий» 0, «средний» 1, «высокий» 2 | Категории с естественным порядком | Порядок задаёшь вручную |
| **Target (по целевой переменной)** | Категорию заменить средним ответом для неё | Много категорий, бустинг | **Риск утечки данных**: считать только на train, лучше с кросс-валидацией |
| **Frequency (частотное)** | Категорию заменить тем, как часто она встречается | Много категорий, частота важна | Разные категории с одинаковой частотой сольются |
| **Binary (двоичное)** | Номер категории в двоичном виде по столбцам | Средне много категорий | Меньше столбцов, чем one-hot |
| **Hashing (хеширование)** | Хеш-функция раскладывает категории по фиксированному числу столбцов | Очень много категорий, потоковые данные | Разные категории могут столкнуться в одном столбце |

## 6. Scaling (масштабирование)

| Method (метод) | Идея | Когда применять | Особенность |
|---|---|---|---|
| **StandardScaler (стандартизация)** | Среднее 0, стандартное отклонение 1 | **По умолчанию**: линейные модели, SVM, нейросети, PCA | Чувствителен к выбросам |
| **MinMaxScaler (минимакс)** | Сжать в диапазон 0..1 | Нейросети, картинки (пиксели), KNN | Один выброс сожмёт все остальные значения в кучу |
| **RobustScaler (устойчивое масштабирование)** | Через медиану и IQR | **Есть выбросы** | Выбросы почти не влияют |
| **MaxAbsScaler (по максимуму модуля)** | Делит на максимальное абсолютное значение, в −1..1 | Разреженные данные, где важно сохранить нули | Не сдвигает данные |
| **Normalizer (нормализация строк)** | Каждую строку привести к длине 1 | Тексты (TF-IDF), косинусное сходство | Работает по строкам, а не по столбцам, в отличие от остальных |

Деревьям, случайному лесу и бустингу scaling не нужен.

## 7. Transformation (преобразование распределения)

| Method (метод) | Идея | Когда применять | Особенность |
|---|---|---|---|
| **Log (логарифм)** | log(x) или log(1 + x) | Сильно скошенные данные: цены, доходы | Только неотрицательные значения |
| **Box-Cox (преобразование Бокса–Кокса)** | Подбирает степень, чтобы распределение стало ближе к нормальному | Строго положительные данные, линейные модели | Сам находит лучший параметр |
| **Yeo-Johnson (преобразование Йео–Джонсона)** | То же, что Box-Cox | Есть нули и отрицательные значения | Обобщение Box-Cox |
| **Quantile (квантильное)** | Перевести значения в ранги и растянуть в нормальное или равномерное | Сложные распределения, много выбросов | Ломает исходные расстояния между значениями |

## 8. Feature Engineering (создание признаков)

| Method (метод) | Идея | Когда применять | Особенность |
|---|---|---|---|
| **Polynomial (полиномиальные)** | Добавить x², x³, x·y | Линейная модель должна поймать кривую | Число признаков быстро взрывается |
| **Interactions (взаимодействия)** | Произведения или отношения признаков: цена / площадь | Смысл в комбинации признаков | Хорошо работает, если опираться на знание предметной области |
| **Binning (разбиение на интервалы)** | Возраст → «18–25», «26–40» | Нелинейная связь, шумные числа | Теряется точность внутри интервала |
| **Datetime features (признаки из даты)** | День недели, месяц, час, выходной ли | Любые данные с датами | Часто дают **самый большой прирост** в табличных задачах |
| **Aggregations (агрегаты)** | Среднее, сумма, число по группе: средний чек клиента | Транзакции, логи, много строк на объект | **Основа сегментации клиентов** по транзакциям |

## 9. Feature Selection (отбор признаков)

| Method (метод) | Группа | Идея | Особенность |
|---|---|---|---|
| **Variance Threshold (порог дисперсии)** | Filter (фильтр) | Убрать почти постоянные признаки | Самый простой, не смотрит на ответ |
| **Correlation (корреляция)** | Filter | Убрать один из двух сильно связанных признаков | Быстро, но видит только линейные связи |
| **Chi² (хи-квадрат)** | Filter | Связь категориального признака с классом | Только неотрицательные признаки и классификация |
| **Mutual Information (взаимная информация)** | Filter | Сколько признак говорит об ответе | Ловит нелинейные связи |
| **RFE (рекурсивное исключение признаков)** | Wrapper (обёртка) | Обучить модель, выкинуть худший признак, повторить | Точнее фильтров, но медленный |
| **Forward Selection (прямой отбор)** | Wrapper | Начать с нуля и добавлять лучший признак по одному | Медленный на сотнях признаков |
| **Backward Elimination (обратное исключение)** | Wrapper | Начать со всех и убирать худший | Похож на RFE |
| **Lasso (L1-регуляризация)** | Embedded (встроенный) | Модель сама зануляет веса ненужных признаков | Тот самый Lasso из нашего разговора о регрессии |
| **Tree Importance (важность по дереву)** | Embedded | Случайный лес или бустинг показывают вклад каждого признака | Завышает важность признаков с большим числом уникальных значений |

## 10. Splitting (разбиение данных)

| Method (метод) | Идея | Когда применять | Особенность |
|---|---|---|---|
| **Holdout (отложенная выборка)** | Train / validation / test один раз | Много данных | **Самый простой.** Результат зависит от случайного разбиения |
| **Stratified (стратифицированное)** | Holdout с сохранением долей классов | Классификация, особенно несбалансированная | Без него редкий класс может не попасть в test |
| **K-Fold (k-кратная кросс-валидация)** | Разбить на k частей, каждая по очереди тест | Мало данных, честная оценка | В k раз дольше обучения |
| **Stratified K-Fold (стратифицированная k-кратная)** | K-Fold с сохранением долей классов | **Стандарт для классификации** | |
| **Group K-Fold (k-кратная по группам)** | Все строки одной группы целиком в train или в test | Один человек, пациент или клиент встречается много раз | Без него модель запоминает людей, а не учится |
| **Time Series Split (разбиение по времени)** | Обучение только на прошлом, проверка на будущем | **Временные ряды** | Обычный случайный split здесь — утечка будущего |
| **Leave-One-Out (исключение по одному)** | Каждый объект по очереди тест | Очень мало данных | Очень медленно на больших данных |

## 11. Imbalance (несбалансированные классы)

| Method (метод) | Группа | Идея | Особенность |
|---|---|---|---|
| **Random Oversampling (случайное дублирование)** | Oversampling | Копировать примеры редкого класса | Риск переобучения на копиях |
| **SMOTE (синтетическое дополнение)** | Oversampling | Создать новые примеры между соседями редкого класса | **Самый известный метод.** Только после split и только на train |
| **ADASYN (адаптивное синтетическое)** | Oversampling | Как SMOTE, но больше примеров там, где класс трудно отделить | Может усилить шум |
| **Random Undersampling (случайное удаление)** | Undersampling | Удалить часть примеров частого класса | Теряешь данные |
| **Tomek Links (связи Томека)** | Undersampling | Удалить пары разных классов, стоящие вплотную | Чистит границу между классами |
| **Class Weights (веса классов)** | Без изменения данных | Ошибка на редком классе стоит дороже в лоссе | **Часто лучший первый шаг**: данные не трогаешь. Это та же идея, что Weighted Cross-Entropy |
